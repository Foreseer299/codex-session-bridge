# v0.2.1 验证范围

这次重点检查子代理状态与连接恢复，不把“进程还在”当成“同步正常”。

- 33 项 Python 测试：安装事务、配置字段拥有权、备份恢复、原件/版本校验、元数据同步和配置 schema 拒绝。
- 5 项 Node 测试：空闲判断、运行资源保护、包定位、停用状态，以及 Codex socket 延迟启动和恢复。
- 桥接回归：实时与历史子代理、嵌套子代理、旧版事件格式、无关聊天隔离、Desktop 专属工具请求隔离。
- 真实 Paseo provider 的隔离测试：完成、失败、中断、运行中四种状态；子代理再次启动；旧历史响应不能覆盖新事件；断线重试与关闭后的定时器清理。
- 独立 Paseo 0.15.3 实例：Git 来源原生插件安装、自动配置和 worker 重启，最终进入 `ready`。
- 关闭测试 Codex 后台后重启 Paseo：插件进入 `waiting_for_codex`；稍后恢复后台，插件自动进入 `ready`，没有手动 reload。
- 插件移除后，三个上游文件恢复原始哈希，托管安装记录撤回。v0.2.0 已验证的停用/重新启用期间移除、字段冲突保护仍有回归覆盖。
- 部署环境只读核对：原生子代理最终结果与 Paseo 接口显示一致，不再把已结束的子代理保留为运行中。

隔离实例使用合成的 Codex Unix socket，没有提交模型任务或复制个人聊天。provider 测试需要将 `PASEO_TEST_PACKAGE` 指向已应用补丁的隔离 Paseo 包；未设置时会明确跳过。普通测试运行 `npm test`。

这些检查不等于所有手机界面的自动化验收，也不验证 Windows SSH 自动连接。插件只负责连接同机 Codex 私有后台，不更改 SSH 设置。仍建议按 [操作指南](installation.md) 检查自己的双向接续流程。

公开发行前检查 Git 历史和解包内容，排除凭据、真实主机路径、会话记录、运行配置和编译缓存；依赖使用固定锁文件并执行 `npm audit`。
